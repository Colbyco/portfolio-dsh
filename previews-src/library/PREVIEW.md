# Library Relational Database API (July 2022) — live preview

**Stage URL:** `/previews/library/` (API console). The API itself: `/api/library/...`.

The original project is an Express + knex REST API over PostgreSQL with no UI. The preview runs
the original routes live in a Vercel Node function (`api/library.js`) and adds a new, self-contained
API console so visitors can call every route.

## Original vs. adapted

Source: `colby-portfolio-dsh-sources/library-relational-database-api/library-api` (read-only reference).

| Original file | Preview file | Change |

| `library.js` | `api/_library/library.cjs` | All knex queries unchanged; only `./db` → `./db.cjs`. |

| `migrations/*.js` (5) | `api/_library/migrations/*.cjs` | Byte-identical content (renamed). Run in original order via `migration-source.cjs` (static requires, so tracing bundles them). Two of them seed J.K. Rowling and the 7 Harry Potter books. |

`api/library.js` mounts the original app under `/api/library` (Vercel passes the original path in
`req.url`), so `POST /author` is `POST /api/library/author`, etc.

### Preview schema shim (disclosed; `api/_library/preview-schema-shim.cjs`)
The 2022 route code and the 2022 migrations disagree; against the original schema 5 of 9 routes can
only return HTTP 500 (verified on PGlite):
- `POST /author`, `POST /book/` insert without an id, but `author_id`/`book_id` are plain
  `int primary key not null` (no default) → `23502 not-null violation`.
- `POST /book/`, `PUT /book/:bookId`, `DELETE /book/:bookId` insert/return `owned`, `on_hand` on `book`,
  but those columns only exist in `inventory` → `42703 column does not exist`.

After the original migrations, one extra step adds only what the original queries expect: identity
defaults on `author.author_id` and `book.book_id` (continuing after the seed rows) and
`book.owned`/`book.on_hand` (`int not null default 0`, same definition as in `inventory`). Original
tables, columns and data are untouched. It is disclosed in one line at the top of the console and
flagged in the ERD. Set `ENABLED = false` in that file for the strictly original schema (write routes
then return the original 500s; the console reads the flag at build time, so rebuild it).

## API console (`public/previews/library/index.html`, built)
Single 29 KB file, no framework, no CDN, no third-party requests. Built by
`node previews-src/library/build.mjs` from `previews-src/library/src/{index.html,app.css,app.js}`:
- **Endpoints** are read from the original Express router (`index.cjs`) and paired with the original
  `// METHOD - Entity - /path - description` comments; the build fails if a route has no comment or
  example. Request examples are hand-written from the fields each handler reads.
- **Schema/ERD** is generated by running the original migrations in a throwaway PGlite and reading
  `information_schema` (columns, types, NOT NULL, defaults, PK, FK, seed row counts); the shim is
  then applied and every column/default it adds is flagged.
- Request builder (path params, optional query string, JSON body prefilled with a valid example,
  JSON validation), Send (button or Ctrl/Cmd+Enter), response panel (status, time, size, content
  type, reset countdown from the `X-Sandbox-Reset-At` header, highlighted JSON or raw text). Ids of
  rows you create are carried into the other forms.
- Dark by default, light theme toggle, honors `postMessage({ type: "portfolio:theme", theme })` and
  `?theme=light`. Keyboard: skip link, Tab order, ArrowUp/Down/Home/End in the endpoint list, visible
  focus, labelled inputs, `aria-live` status. Layout: 3 columns ≥ 1120 px, 2 columns ≥ 760 px,
  single column below; no horizontal page scroll at 360 px.

## Database
PGlite in memory, one per function instance. On the first request (and every 30 minutes, checked
lazily) the wrapper drops and recreates the `public` schema, runs the 5 original migrations (tables +
seed) and applies the shim. The original down-migration of the book seed is invalid SQL (no
separators), so resets rebuild instead of rolling back.

## Safety wrapper (`api/library.js`, before the original routes)
- JSON body limit 10 KB (413); malformed JSON → 400; parsed before the original `express.json()`,
  which then skips.
- Every string value (and key) in the body ≤ 200 characters (400); request path ≤ 300 characters (414).
- Writes (POST/PUT/PATCH/DELETE): 20 per minute per IP (`x-real-ip` / `x-forwarded-for`), in memory →
  429 JSON with `Retry-After`. Reads are not limited.
- Errors are JSON without stack traces. PostgreSQL errors keep the original 500 status and add
  `database: { code, message }` (the PostgreSQL message, no SQL text) so the sandbox is
  understandable. Unknown paths → JSON 404 (the original sent Express' HTML "Cannot GET").
- `Cache-Control: no-store`; data resets to the migration seed every 30 minutes.

## Deployment
`vercel.json` needs PGlite's runtime assets, which file tracing misses (verified with `@vercel/nft`):
```json
"functions": {
  "api/library.js": { "includeFiles": "node_modules/@electric-sql/pglite/dist/{pglite.wasm,pglite.data,initdb.wasm}" }
}
```
All `api/_library/**` files are traced already. Cold start ≈ 1 s; ≈ 340 MB RSS per instance.

## How to test
```powershell
node scripts/dev-server.mjs --root public --port 4410
node previews-src/library/smoke-test.mjs   # 24 checks: every route, writes, 404s, DB errors, limits
python qa/previews/weather_library_screenshots.py   # qa/previews/library-*.png (+ weather)
python qa/previews/weather_library_keyboard.py
node previews-src/library/build.mjs         # rebuild the console after editing src/ or the shim
```
Reset test: start the server with `$env:LIBRARY_PREVIEW_RESET_MS='8000'`, create/delete rows, wait,
and `GET /api/library/books` is back to the 7 seeded books (ids restart at 8, authors at 2).

## Known limitations
- State is per function instance: concurrent instances have separate databases; a cold start resets.
- Rate limiting is per instance (in memory), not global.
- Any visitor can delete or rename seeded rows; others see that until the next 30-minute reset or
  cold start.
- `published_date` is returned as an ISO timestamp (`1997-06-26T00:00:00.000Z`), as node-postgres did
  on a UTC host.
- `inventory` has no routes in the original API, so it stays empty.
